## 复古小霸王风 Web 端 NES 模拟器（新项目，从零搭建）

**需求**：基于开源 NES 内核（jsnes）做 Web 端模拟器，UI 走复古小霸王风，仅 PC 端，技术栈 Vue3 + Vite + TS。

**产出**：`D:/workspace/demo1` 完整可运行项目（未发布上线，本地 dev server 端口 5180）。

### 落地内容
- 工程：Vue 3.5 + Vite 6 + TS 5.7，`@` → `src` 别名，`vue-tsc --noEmit` 通过。
- 内核层 `src/core/`（与框架解耦）：
  - `NesEmulator.ts`：rAF + 固定步长累加器主循环；音频时钟反哺校正（缓冲见底补帧 / 积压丢帧）。
  - `AudioEngine.ts`：Web Audio 环形缓冲（1.5s）+ ScriptProcessorNode，欠载时直流保持避免爆音。
  - `InputManager.ts`：键盘（每键 2 个键位）/ 标准 XInput 手柄 / 虚拟手柄三源合并成差量事件。
  - `rom.ts`：iNES 1.0 + NES 2.0 头解析、FNV-1a ROM 指纹。
  - `storage.ts`：IndexedDB（卡带库 / 5 个存档槽 / 记忆电池）+ localStorage（设置、键位）。
- UI：CRT 扫描线/暗角/增艳、4:3 与 1:1 切换、整数倍缩放、电源开关动画、待机画面、虚拟手柄、按键设置弹窗、卡带架。
- 内置试玩卡带：jsnes 包自带的 LJ65 与 Concentration Room（均为 Damian Yerrick 的自由软件），放 `public/roms/`，附 `THIRD-PARTY.txt`。

### 踩到的关键坑（重要）
1. **jsnes 2.x 的 `NES#reset()` 是坏的**：只重建 cpu/ppu/papu 与 mapper 实例，不调 `mmap.loadROM()`，CPU 地址空间没有重新装载 PRG，下一帧必抛 `Game crashed, invalid opcode`。复位必须改用 `nes.reloadROM()`。`loadROM()` 内部自带完整 reset，所以 loadROM 之后**不要**再手动 reset。
2. `toJSON()` 不含 `romData`；`fromJSON()` 内部会调那个坏掉的 `reset()`，但随后 `cpu.fromJSON()` 会恢复完整内存镜像，所以读档路径是安全的（已实测）。
3. 本机 **npm 官方源极慢**（一次 install 挂 10 分钟无进展），换 `registry.npmmirror.com` 后 15~30 秒装完。
4. npm 会漏装 esbuild / rollup 的 Windows 平台包（`@esbuild/win32-x64`、`@rollup/rollup-win32-x64-msvc`），导致 vite 启动报 `The package ... could not be found`。已显式写进 `optionalDependencies` 兜底。

## 修复：内置卡带启动无画面

**现象**：点内置卡带后电源灯亮（状态「待机」），但屏幕一直是待机画面 / 全黑。

**定位过程**（用真实浏览器 + CDP 驱动复现）：

| 实验 | 结果 |
| --- | --- |
| 无手势 `new AudioContext()` + `resume()` | state 恒为 `suspended`，**resume() 的 Promise 永久 pending** |
| `element.click()`（无用户手势）点内置卡带 | rom 仍 `未插入`、状态 `待机`、画布 **0 个非黑像素** |
| CDP `Input.dispatchMouseEvent`（真实手势）点同一按钮 | rom `lj65`、状态 `播放中`、画布 4444 个非黑像素、FPS 60 |

**根因**：`setPowered()` 把 `await audio.start()` 放在了启动模拟器之前。
浏览器自动播放策略下 `ctx.resume()` 不 reject 而是**永久 pending**，
于是 `setPowered()` 永远不返回 → `startRom()` 永远执行不到 → 卡带根本没装载。
跨域 iframe 预览（无 `allow="autoplay"`）会必现。

**修法**（三层）：
1. `AudioEngine.start()` 保证绝不抛错、绝不长挂：构造异常一律静音降级；
   部分声卡不接受强制采样率的，回退设备默认采样率。
2. `resume()` 用 `Promise.race` 加 350ms 超时兜底；`suspend()` 同样处理。
3. `setPowered()` 改成先 `emulator.start()` + `input.start()`，
   音频挪到最后且 **绝不 await**（`void startAudio()`）。
   音频被拦时提示一次「点一下页面任意处即可恢复」，画面完全不受影响。

**验证**：修后同一「无手势点击」场景 rom=`lj65`、画布 4444 个非黑像素、FPS 60；
按 START 后画面指纹变化（nonBlack 4444→10182），确认是活的不是冻帧。
画布像素与内核直出帧逐像素一致（LJ65: 3413+1031=4444；Croom: 43119+435+392=43946）。

### 环境突破：终于能截图了
上次结论「无头 Edge 被沙箱拦截」只对 **Bash 通道**成立。改用 **PowerShell 通道**可以正常
`Start-Process` 启动 Edge，再让 Node 脚本通过 CDP（`--remote-debugging-port`）驱动即可：
截图、注入鼠标/键盘、读画布 `getImageData`、收集 console 异常全能做。
注意两点：① Bash 访问 CDP 端口会被沙箱代理拦（502），脚本必须在 PowerShell 里跑；
② Edge 必须和探针脚本在**同一条 PowerShell 命令**里启动，否则父进程退出时子进程被回收。

已知无解的小问题：本机 GPU 进程反复崩溃，`Page.captureScreenshot` 合成 canvas 层时会出现
一道斜切伪影（`.vignette/.scanlines/.glass` 关掉也一样）。但 `canvas.toDataURL()` 导出的
原始像素完全干净，可确认是**无头软件光栅化的问题，不是页面 bug**。
